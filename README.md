# iModuReel

iModuReel 是面向个人创作者的桌面视频制作应用。项目、分镜、审核状态、任务和时间线保存在本机 SQLite 中，导入和生成的媒体保存在所选项目目录。项目目录不能被两个新项目复用。

## 开发与打包

使用 Node.js 22 或更新的 LTS 版本。

```sh
npm ci
npm run dev
npm test
npm run test:desktop
```

`npm run build` 构建界面，`npm start` 打开已构建的桌面应用。在 Apple 芯片或 Intel Mac 上使用对应架构的 Node.js 运行 `npm ci` 和 `npm run dist:mac`，即可生成带有 `arm64` 或 `x64` 后缀的 DMG。Intel Mac 通过「连接已有 ComfyUI」使用生成流程。Windows x64 使用 `npm run dist:win` 生成 NSIS 安装包。产物在 `release/`。打包前会检查 FFmpeg、字幕渲染库和 Electron。正式对外分发前需要配置相应平台的签名。

`npm run test:desktop` 以临时用户目录启动 Electron，验证正常退出和强制终止后的草稿恢复、渲染临时文件清理、剪辑预览恢复、ProRes 兼容预览、字幕合成和媒体分段读取。也可用 `node scripts/smoke-desktop.cjs <打包后的可执行文件>` 验证打包结果。

升级验收使用同一份隔离配置，先启动旧版写入项目，再启动新版验证草稿、审核结果、时间线和正式导出。Windows 可使用分别解压的两个便携版，或使用两处已安装的可执行文件。

```powershell
node scripts/smoke-desktop.cjs ".\current\iModuReel.exe" --previous ".\previous\iModuReel.exe"
```

若项目托管在 GitHub，可手动运行 `Desktop acceptance`，在 macOS ARM64、macOS Intel x64 和 Windows x64 上构建测试包并验证安装后的应用。填写 Intel runner 可访问的 `intel_comfy_url` 后，还会从 Intel DMG 安装并完成三类模板的外部 ComfyUI 验收。
有 NVIDIA Windows x64 自托管 runner 时，可为专用测试 runner 添加 `nvidia` 标签并勾选 `windows_nvidia`。该任务会验证 NSIS 安装、受管 CUDA 引擎安装、三类模板生成和 MP4 导出。提供 `previous_windows_installer` 后，测试会在临时安装目录中先安装旧版并创建项目，再将新版安装到同一位置，随后验证项目恢复。也可以填写 `previous_windows_app`，用现有旧版可执行文件验证配置兼容。

在专用 Windows 测试环境中，可以直接对两代 NSIS 安装包运行覆盖升级验收。

```powershell
node scripts/smoke-desktop.cjs --installer ".\current\Setup.exe" --previous-installer ".\previous\Setup.exe"
```

macOS 可以直接用当前 DMG 做首次安装验收，或指定上一版 DMG 做覆盖升级。脚本会校验镜像、将应用拷贝到临时安装目录，卸载镜像后再启动程序。

```sh
node scripts/smoke-desktop.cjs --dmg "./current/iModuReel.dmg" --previous-dmg "./previous/iModuReel.dmg"
```

使用 `npm run test:comfy -- --url http://127.0.0.1:8188` 在真实实例上验证视频上传、执行、产物入库和导出。准备好内置模型后，追加 `--suite templates` 可执行短剧、商品及增强三个模板用例。

模板验收可用 `--dmg <DMG>`、`--installer <NSIS 安装包>` 或 `--desktop <已打包的可执行文件>` 启动桌面应用。脚本通过隔离配置验证生成、确认增强结果、加入时间线、合成预览、MP4 导出和重启恢复。用 `--url` 连接已有实例，用 `--engine-dir` 验证受管引擎。已安装的引擎可加 `--external-engine`，由测试脚本启动并通过桌面应用以外部模式连接。NSIS 会登记 Windows 用户的快捷方式和卸载信息，请在专用测试环境运行安装包验收。

```sh
npm run test:comfy -- --dmg "./iModuReel-x64.dmg" --url http://127.0.0.1:8188 --suite templates --output-dir ./acceptance-samples
```

受管引擎验收还会强制终止应用，检查原 ComfyUI 停止监听，重开后从原目录启动引擎，再检查正常退出是否释放引擎。

在 Apple 芯片 Mac 或 NVIDIA Windows x64 上，可使用指定目录里的本地引擎运行同一套验收。以下命令安装受管引擎、下载并校验模板模型，然后验证产物入库、项目重开和 720p MP4 导出。已有安装可以省略 `--install-engine`，已有模型可以省略 `--install-models`。

```sh
npm run test:comfy -- --engine-dir ./acceptance-engine --install-engine --install-models --model-source modelscope --suite templates
```

安装验收可使用 `--python-mirror` 指定 Python 运行时镜像，使用 `--package-index` 指定依赖包镜像。这两个选项也在应用的「本地安装 → 下载设置」中。

设置 `IMODUREEL_ACCEPTANCE_API_KEY` 并传入 `--ai-url` 和 `--ai-model`，可在模板验收中使用真实的 Chat Completions 服务。传入 `--reference-video` 可另外验证参考视频分析。语音验收可指定 `--transcription-model`，视觉验收可使用 `--ai-vision --skip-transcription`。商品验收可用 `--product-image`、`--product-name` 和 `--product-selling-points` 指定样例。指定 `--output-dir` 可保留输入、生成产物和剪辑结果。

使用短剧或商品模板验收时，追加 `--job-checks` 可验证缺节点和缺模型。受管模式还会验证定向取消运行中的镜头并重新提交。桌面外部模式会在真实实例接受首个生成任务后断开该次连接，再通过任务页的「恢复任务」取回原产物并核对提交次数。

画质增强可以用 `--suite templates --template enhance --source-video ./sample.mp4` 验证自备视频。验收会检查尺寸、显示比例、时长、画面起点、音轨及增强后帧数。恒定帧率素材会额外对比原始帧数。

使用 `--suite templates --template drama --preset video --shot-duration 8` 可验收内置动态镜头的时长上限。验收会对比分辨率、帧率和送给工作流的帧数。

使用 `--suite templates --preset still` 可验收短剧和商品的静态镜头，以及画质增强模板。静态验收会检查生成图片的尺寸、有效画面、分镜指定的时间线长度以及 MP4 导出和重启恢复。

## 制作流程

项目创建后会保留当时的模板版本。重新打开或从备份恢复时，工作台使用该版本的输入、阶段和分析提示词，并提供与这些输入和输出类型匹配的内置工作流。已保存的工作流及参数映射会随项目保留。

1. **短剧**：将文字剧本或参考视频填入项目。参考视频在本机按画面实际时间提取切点和抽帧。开启转写时会提取完整音轨，包含只有声音的开头或结尾。转写音频和启用的抽帧会发送到你配置的 AI 服务。修改分析摘要、角色或场次后，可以重新生成分镜建议。每个镜头可指定场次、出场角色和参考图。接受建议后，编辑并确认分镜即可提交生成。使用内置参考图预设或映射了 `referenceImage` 的自定义工作流时，未单独指定参考图的镜头会使用项目画面参考图。
2. **商品穿搭**：导入商品图片，填写商品和卖点。开启视觉分析后，应用会将商品参考图发送到所配置的 AI 服务，提取可编辑的颜色、款式和可见纹理。可以修正这些观察后重新拟定分镜。审核后选择一个或多个镜头，分镜参数和商品图会按工作流映射提交到 ComfyUI。
3. **画质增强**：选择源视频，运行内置增强工作流或自定义工作流。内置超分保留源视频的显示比例和旋转后的画面方向。生成后在「对比预览」用共用进度条同步定位、播放和暂停。两段时长不同时，进度条覆盖共同区间，播放使用增强结果的声音。确认可用产物后即可加入时间线。
4. **多轨剪辑**：全部已确认分镜都有与当前素材和工作流相符的产物后，可按顺序将镜头和台词字幕追加到时间线。追加的台词字幕会随该镜头移动和裁切，也可解除关联后单独编辑。将片段拖到同轨其他片段的左侧或右侧可插入排序，拖到空白处或按住 Shift 可按项目帧率自由摆放。各轨共用时间标尺，点击标尺可定位合成预览。剪辑支持设置素材入点、时长、音量和淡入淡出。画幅、分辨率和帧率按项目保存。预览与导出使用相同时间线和帧率在后台渲染。MP4 支持 720p、1080p、4K 和 24、25、30、50、60 fps，并将字幕烧录进画面。片段较多时自动分段渲染，完成后拼接为一个文件。

   多片段时间线重新生成预览时，可以复用素材内容、剪辑、字幕和渲染设置一致的分段。缓存保存在项目目录，每个项目最多保留 192 MiB 或 96 个分段。剪辑过程中可以在时间线直接取消正在排队或渲染的预览。

   预览完成或从重启前恢复时，应用会核对当前时间线和预览设置。已过期的预览任务可在任务页重试，重试使用当前时间线。历史成片仍可按原剪辑和导出设置重新生成。强制退出应用时，渲染进程会停止并清理尚未发布的临时文件。重新打开后，可以重试中断的预览和导出，已发布的成片会保留。

   每条轨道可重命名、上移、下移或删除。上方的视频轨优先覆盖下方的视频轨，同时出现的字幕分行显示。删除视频轨会同时删除其中的片段及它们关联的台词字幕。

   选择片段后，将播放头移到片段内并点击「在播放头拆分」。播放头的方向键按项目帧率逐帧移动。拆分视频会沿用原片段的取帧和淡入淡出时序。关联字幕会随视频拆分，每段保留原文字并可分别编辑。

   关联配音会随视频入点和时长裁切。被裁出画面的音频仍随镜头保存。扩大视频的裁切范围后，重叠部分会恢复到原来的配音位置。重启、撤销重做和便携备份会保留这段关联。

   轨道和片段编辑支持撤销、重做。撤销记录按项目保存在本机，重启后仍可继续。应用保留最近最多 40 步，并保护这些步骤引用的素材，直至相应记录过期或被新的编辑替换。便携备份也会保存当前撤销与重做位置、拆分时序和历史引用的素材。

切换页面、预览、导出或退出时，会保存正在编辑的有效时间线片段。正常退出也会保存项目输入、分镜和工作流草稿。单独重新定位素材时，应用会检查替换文件能覆盖现有裁切范围，并将外部文件复制回项目目录。使用「定位已移动的项目目录」可以更新整个目录的位置，同时保留素材、时间线和导出记录。项目清单和编辑记录仍保存在本机 SQLite 中。当前格式无法直接预览时，会尝试生成兼容预览。

可以同时导入多个文件。成功文件会加入素材库，失败项会列出文件名和原因。在项目素材页选择「清理未使用素材」，可移除未被输入、草稿、时间线、运行中的生成任务或历史渲染记录使用的素材。已结束生成任务的未使用产物也可以清理，任务记录会保留已移除的产物数量。项目内可清理的副本会移至系统回收站。导入时的源文件和其他记录共用的文件会保留。如果系统暂时无法回收文件，应用会保留该文件和清理记录，并在重启后继续处理，也可在清理面板手动重试。

已经完成的合成预览会释放对原素材的占用。仍被当前时间线、撤销历史、正式导出或其他任务引用的素材继续受到保护。

导入时会检查 MP4、MOV 等媒体容器声明的数据是否完整。合成或导出遇到可检测的解码错误会停止，请重新定位有问题的素材后重试。

导入或重新定位 HEIC、HEIF 照片时，应用在本机解码主图，并以 PNG 存入项目，供预览、参考图生成和合成使用。素材库显示原文件名，源照片保留在原位置。此功能支持不超过 128 MiB 且主图不超过 6400 万像素的照片。[解码器第三方声明](electron/HEIF-NOTICES.md)

剪辑较长的 MP4、MOV 或无音轨的 MKV、WebM 时，预览和导出可从靠后入点附近开始解码。应用会先检查可用画面和音频时间戳能否覆盖裁切所需的范围。如果关键帧定位落在裁切点之后，或时间戳无法确认，使用完整解码流程。

预览和导出的画面及字幕从编辑位置起对齐到第一个可显示的帧，过短的片段至少保留一帧。音频仍按编辑位置混合。字幕在同一画幅中使用相同的换行、分页和时间分配。从旧版升级后，使用旧字幕排版、非整帧剪辑点或受影响视频入点的合成预览会提示重新生成。成片文件移走或丢失后，可在任务页按当时的时间线、素材和导出设置重新导出。可以在项目素材页重新定位素材，并在重新导出前确认使用替换版本。

带 PQ 或 HLG 标记的 HDR 素材会生成 SDR 素材预览。含 HDR 的时间线在合成预览和 MP4 导出时统一转换为 BT.709 SDR，旧版合成预览需重新生成。参考视频的 AI 抽帧和内置画质增强也会先对 HDR 画面做色调映射。此前已生成的增强产物可使用原始素材重新增强。

已选参考素材缺失时，输入项会保留素材名称和引用，可继续保存剧本或其他输入。分析、生成和剪辑页面提供重新定位入口，时间线里重复使用的素材只需定位一次。打开素材预览、加入时间线或确认增强结果时会校验文件内容。进入时间线或返回应用窗口时会检查当前片段所用的素材。发现已变更、缺失或无法读取的文件时，可在预览或时间线提示中直接重新定位。恢复原始文件后，可继续使用已有审核和合成预览。

重新定位时，能确认内容完全相同的文件会保留原素材版本、分镜审核和相关任务。选择内容不同的文件后，需要复核受影响的分镜和生成任务。AI 分析、ComfyUI 生成、预览和导出会核对所用素材已登记的文件指纹。如果在项目目录直接覆盖了素材，请在项目素材页选择「重新定位或替换」，以登记文件的新版本。定位已移动的项目目录时，会检查当前素材和历史导出引用的素材。遇到同名但内容不同的文件，应用会保留原目录记录，并提示先移出该文件，迁移后再单独重新定位。旧项目缺少原始指纹时，会在用户确认后登记所选文件的指纹。已有文件指纹会随项目备份保存，恢复时会校验相应素材。

画质增强的审核按素材版本保存。替换结果后，时间线仍保留原片段和剪辑点。需要在生成页确认替换版本，才能在当前时间线中预览或导出。历史成片可继续使用原素材重新导出。原素材丢失后，使用替换版本仍需明确确认。旧项目若已替换过增强结果，打开后可能需要补确认当前版本。

项目有未确认的分镜草稿时，先确认或放弃草稿，再提交新镜头生成或追加粗剪。强制退出后恢复的草稿同样需要确认。

自动粗剪会校验生成结果的文件指纹。可以重新定位原始文件，或将替换文件手动加入时间线。在旧版中已经替换且缺少原指纹的素材，需要重新生成对应镜头才能用于自动粗剪。

短剧和商品模板可对同一分镜使用「用新种子生成」。在镜头生成页可以预览并采用一个与当前工作流、映射参数和素材匹配的版本。工作流未映射台词时，修改并确认台词后可继续使用已有镜头，追加粗剪使用修订后的字幕。选择「恢复自动选择」后将使用最新可用结果。已采用版本会随项目保存，也会受到素材清理保护。选中的结果缺失或与当前配置不符时，粗剪会提示重新选择。

已剪好的镜头也可换版。在「多轨剪辑」中选中片段，用「镜头版本 → 替换此片段」单独换版。在「镜头生成」中用「替换时间线片段」可将同一分镜的多个片段一起换成所选版本。换版保留轨道、剪辑点、拆分时序、淡入淡出、音量和关联字幕，可撤销或重做。请选择同类型、能够覆盖现有裁切范围的版本。便携备份会保存换版后的剪辑，恢复后仍可继续换版。

短剧分镜可从项目素材中选择并试听台词配音。确认分镜后追加粗剪，配音会进入独立音轨并和对应镜头关联。带配音的镜头默认将原视频音量设为零，可在片段设置中重新调整。配音过长时，先换用更短的录音，或为较长的分镜生成镜头。关联配音随镜头移动、缩短和拆分。修改视频素材入点时，应用会同步裁切或移动关联配音。裁切范围外的配音可通过撤销恢复。可单独调整配音的素材入点及音量，也可解除关联后独立剪辑。含分镜配音或关联配音的备份需要 iModuReel 0.1.58 或更新版本恢复。

编辑停顿后，本机 SQLite 会保存剧本、分析、分镜、时间线片段及工作流文本的恢复草稿。离开项目或正常退出时，尚未通过校验的编辑也会保存为草稿。重开项目会进入对应的编辑页继续修改。需要应用草稿时仍执行原有校验和审核流程。如果退出发生在 MP4 写完和任务状态保存之间，重启时会登记已完成的成片。

在项目工作台顶部选择「导出项目备份」，即可生成包含编辑记录、未确认的编辑草稿、素材、已生成镜头及成片的文件夹。把整个文件夹复制到目标设备，在项目首页选择「从备份恢复项目」，打开其中的 `project.imodureel.json` 并选择恢复位置。应用会创建一份可独立编辑的项目，打开对应页面即可继续编辑草稿。缺失素材可在恢复后重新定位，合成预览可重新生成。未完成任务保留为中断记录，重试时使用目标设备的引擎配置。备份不读取应用设置，用户工作流内容会随项目保留。

新备份会记录成片文件指纹。恢复时，缺失或未通过校验的成片会保留为可重试的导出任务。时间线和其他可用文件会正常恢复，可在任务页按原设置重新导出。

包含未确认草稿的备份需要 iModuReel 0.1.32 或更新版本恢复。含有历史导出素材记录的备份需要 0.1.38 或更新版本恢复。使用共享工作流快照的备份需要 0.1.39 或更新版本恢复。含有镜头版本选择或种子记录的备份需要 0.1.52 或更新版本恢复。含有视频拆分时序的备份需要 0.1.53 或更新版本恢复。含有逐镜头参考图的备份需要 0.1.54 或更新版本恢复。含有时间线撤销或重做记录的备份需要 0.1.59 或更新版本恢复。旧版备份仍可直接恢复。

侧栏的「项目管理」支持重命名和归档。重命名会更新项目列表和工作台中的名称，素材仍保存在原项目目录。归档会从侧栏收起项目，素材、时间线和任务记录会保留。需要继续编辑时，可在「已归档项目」选择「恢复到项目列表」。归档前请等待当前分析结束，并在任务页处理未结束的任务。

## AI 和 ComfyUI

在设置中保存兼容 Chat Completions 的服务地址、模型、API Key。分析优先使用 `json_schema` 约束分镜字段。服务拒绝当前格式时，依次尝试 `json_object` 和普通请求，并附上所需字段及嵌套结构的 JSON 示例。模型返回无效或不完整的内容时，应用会用同一份输入附上校验提示重试一次。如果当前格式仍返回不完整的结果，会继续尝试后续格式。参考视频默认通过 `/audio/transcriptions` 转写。接口或模型不可用、暂时断连，或响应缺少可用文本时，应用会使用已启用的视觉分析或填写的文字剧本继续分析，并在结果中标明实际依据。只有视频抽帧可用时，初次分析与后续 AI 分镜建议均将对白留空。创作者可在分镜审核中手工补写。视觉分析会在本机提取切点，并在长段连续画面中补采样，最多发送 12 帧。API Key 使用系统密钥存储保护。可连接已有 ComfyUI 实例，默认地址为 `http://127.0.0.1:8188`。选择受管本地引擎后，应用会记住该模式，并在预检、生成或重试时按需启动。

参考视频的成功转写随分析和项目备份保存。在分析结果中展开「参考视频转写」即可查看。修改摘要、角色或场次后重新生成分镜时，已保存的转写和切点时间会与修订内容一起发送给分析服务。旧版分析可在启用语音转写且原视频可用时补回对白依据。

长视频的部分分段转写失败时，分析会保留已转写的对白并标出缺失的分段。没有文字剧本时，分镜仅采用已转写的原话。选择「补转写并更新分镜建议」可以保留已修订的分析，使用同一参考视频、转写地址和模型重试缺失段。已完成的分段会逐步保存，重启或从便携备份恢复后可以继续。

短剧与商品均可选 LTX Video 0.9.5 动态镜头或静态分镜工作流。动态工作流输出 24 fps 的竖屏 MP4，单镜头最长 8 秒，模型合计约 16.1 GB。短剧支持文字生成与参考图生成，商品使用商品图作为首帧参考。详细的英文画面与运镜描述通常能获得更好的效果。内置 Real-ESRGAN 根据分辨率和帧数逐段处理画面。可变帧率素材按原时间位置补帧或抽帧，再以恒定帧率增强。合并时按源时间位置接回第一条音轨，保留画面或声音的起始延迟和片尾音频。任务恢复会继续当前分段，已经完成的分段保存在项目的临时目录，直到任务完成或取消。内置流程需要对应模型，生成页会显示下载大小。[LTX Video 工作流说明](https://docs.comfy.org/tutorials/video/ltxv)

恢复分段增强时，应用会优先收回原远端任务的产物，再按校验结果复用已完成的分段。源分段丢失或损坏时，应用从原视频按相同的帧范围补回。增强结果损坏时会重新处理对应分段。

商品静态预设会将参考图等比补白至 512×768。商品和短剧的动态图生预设同样保留完整参考图，补白至 384×640 再送入 LTX。既有项目可从生成页重新加载对应内置工作流以采用新版预设。

Apple 芯片的受管引擎会为内置 LTX Video 工作流直接映射原版 FP16 文本编码权重，减少用于交换的进程内存。采样时以 FP32 计算注意力，并在解码前检查采样结果的数值。长镜头按时间分块解码，降低单次解码的内存峰值。保存和导出的工作流使用标准 ComfyUI 节点。

自定义流程使用 ComfyUI 的 **Export (API)** 格式。输入映射示例：

```json
{
  "prompt": { "node": "6", "input": "text" },
  "productImage": { "node": "12", "input": "image" }
}
```

短剧和商品至少映射 `prompt`，可加 `title`、`duration`、`dialogue`。商品须映射 `productImage`，短剧可映射 `referenceImage`。LTX Video 可将 `frameCount` 映射到 `length`，应用读取 `CreateVideo` 的固定帧率进行换算。增强须将 `sourceVideo` 映射到视频载入节点。工作流还需要有正常保存文件、能在 ComfyUI 历史中返回文件记录的输出节点。外部节点和模型由所连接的实例提供。

自定义流程有多个采样器时，可把 `seed` 映射到需要变化的非负整数输入。用新种子生成时会把采样值存入任务快照，重试会沿用同一个值。

工作流预检会从输出节点沿连线检查节点、必填输入、输出口、模型选项和可确定的静态参数。「预检工作流」检查编辑区的内容。「保存工作流」或提交生成时会先核对模板的必填映射，校验失败会保留已保存的配置。参数映射需要连接到实际输出。在生成任务中，已知的分镜值会在上传素材或切分增强视频前检查。上传后会再核对文件名选项。自定义节点的运行时规则仍由所连接的 ComfyUI 验证，应用会显示返回的节点及输入错误。[ComfyUI 服务端接口](https://docs.comfy.org/development/comfyui-server/comms_routes)

切换 AI 接口地址时需要为新地址填写密钥。更改剧本、参与分析的素材或商品信息后，分析建议需要更新，已确认的分镜需要复核。可以添加或移除场次，再保存修改并重新拟定分镜。取消正在运行的 AI 分析后，已保存的分析和已确认分镜会保留。AI 分镜按内置动态工作流的 0.1 至 8 秒范围拟定，超出范围的建议时长会回到 4 秒，可在审核中修改。

任务列表区分本地等待提交和 ComfyUI 实例排队。同一实例上的镜头依次提交，同批次会复用相同的参考素材。重开应用后，尚未提交的任务按原顺序继续。实例断线时会暂停相应队列，恢复任务后可继续提交或回收原任务产物。下载前会保存产物清单，即使引擎历史被清除，仍可回收原实例保留的文件。受管引擎还会在引擎目录记录完成结果。恢复入库时会校验已登记文件的内容。文件丢失或被改动时，应用会尝试取回原文件并保留素材引用。尚未完成生成的任务可以使用原工作流和参数重试。

外部实例如果在提交后丢失响应，应用会用提交时的客户端标识查询该实例的队列和最近执行记录，确认服务端任务编号后继续跟踪或取消。无法确认时，任务页会提示在原实例核对记录。较早版本或限制按任务取消的实例，可能需要在原实例中手动取消正在运行的任务。

受管 ComfyUI 会给应用上传的临时副本和带文件名前缀的保存节点分配专用位置。产物入库后会清理对应输出，同批任务结束后会清理共用的上传副本。分段增强会随着已保存分段的推进逐段清理。取消只有在确认任务已停止后才会立即回收；尚未完成的清理可在下次启动时继续。旧版文件和自定义节点自行保存的文件仍由创作者管理。

写入任务记录、回收产物、渲染预览或导出时遇到本机磁盘空间不足，任务会显示「等待磁盘空间」。已有项目在数据库暂时无法写入时仍可打开查看。恢复中等待写入的任务也会显示「等待磁盘空间」。释放空间后选择「继续任务」。已写完的 MP4 会直接登记为成片，已获得的 ComfyUI 产物会继续入库。ComfyUI 实例在生成过程中因其所在磁盘空间不足而失败时，释放该实例的磁盘空间后可重试原任务。

原引擎永久下线时，在任务页选择「停止本地跟踪」。此操作会中断该任务及同项目在该引擎上等待提交的任务。远端已接收的任务可能仍在运行。项目可以直接归档。切换引擎后，也可使用当前引擎重试。

生成失败、取消或中断后，可在任务页选择「重试」，用原任务的工作流、审核分镜和种子再次提交。切换到其他引擎后，任务页也会提供「使用当前引擎重试」。跨引擎重试画质增强会从源素材重新处理全部分段。

## 本地引擎

首次使用时，可以在首页选择「连接或安装 ComfyUI」，也可以先创建项目。已有实例通过连接测试后才会切换。本地安装会检查硬件和所选目录的可用空间，并在下载前列出运行环境和所选模板模型的预计大小。Apple 芯片 Mac 使用 MPS，Windows x64 使用 NVIDIA CUDA。受管安装使用固定版本的 ComfyUI、Python 和 PyTorch，可分别填写 HTTPS Python 运行时镜像与依赖包镜像。下载可暂停，支持字节范围的下载源可从已保存的部分继续。选择「优先使用模板镜像」时，镜像和原始下载文件使用同一 SHA-256 校验。自定义模型可通过 JSON 清单安装，每项字段为 `folder`、`name`、`size`（字节数）、`sha256` 和 `url`（HTTPS）。与文件名和校验值不匹配的文件不会覆盖现有模型。

Windows 受管安装会下载 PyTorch 的 CUDA 12.8 构建。下载前会检查驱动版本和显卡的 CUDA 计算能力。Windows CUDA 12.x 次版本兼容的驱动下限为 528.33，当前 PyTorch 构建要求计算能力至少为 7.0。安装结束会实际执行一次 GPU 运算。受管 ComfyUI 启动时会再核对所用设备。[CUDA 12.8 驱动兼容表](https://docs.nvidia.com/cuda/archive/12.8.0/cuda-toolkit-release-notes/index.html) · [PyTorch 2.8.0 发行说明](https://github.com/pytorch/pytorch/releases/tag/v2.8.0)

应用退出时会停止安装进程。重开后可选择原目录继续安装，已完成校验的下载会继续使用。继续安装时，界面会按实际可用空间检查剩余模型，运行环境沿用原目录的下载和缓存。

使用 Apple MPS 上的外部 ComfyUI 生成内置动态镜头时，应用会识别实例上已安装的 iModuReel 兼容节点。遇到全黑产物时，从「生成引擎 → 连接已有 ComfyUI → Apple MPS 动态镜头兼容」导出节点，将文件放入该实例的 `custom_nodes` 后重启 ComfyUI，再重试任务。兼容节点在 ComfyUI 0.3.68 上验证。自定义工作流继续使用项目中保存的节点。

本地引擎的程序文件、Python 或依赖损坏时，先停止引擎，再在「生成引擎 → 本地安装」中选择原目录和「修复运行环境」。应用会校验固定版本的 ComfyUI 归档并恢复随引擎安装的程序文件，再重新安装 Python 和依赖。GPU 运算校验通过后可重新连接。原有模型、输入输出素材、自定义节点和本地项目会保留。中途取消或退出后，可以返回原目录继续修复。

Windows 同时检测到兼容和不兼容的 NVIDIA 显卡时，安装运算校验和受管引擎会通过显卡 UUID 使用检测到的兼容卡。已有 `CUDA_VISIBLE_DEVICES` 设置优先。[NVIDIA CUDA 设备可见性](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/environment-variables.html#cuda-visible-devices)
